Обучение модели принятия решений методом обратного обучения с подкреплением

---

Исходные данные для обучения

Основой для обучения модели послужили экспертные траектории, собранные в ходе работы симуляции. Каждая запись датасета содержит четыре значимых поля: число автомобилей в очереди highway1 в момент наблюдения (highway1_len), пропускная способность полосы highway1, выраженная в виде задержки выезда (drain_delay_h1), сигнал готовности агента highway2 (can_take2), а также целевая переменная — решение агента highway1 о готовности принять автомобиль (can_take1). Поля timestamp и step из обучения исключались, поскольку несут лишь идентификационную функцию и не отражают содержательное состояние среды. Таким образом, задача сводилась к следующему: по трём наблюдаемым характеристикам текущего состояния (загруженность и пропускная способность собственной полосы, сигнал от соседнего агента) восстановить скрытую функцию вознаграждения, которой руководствовался эксперт при принятии двоичного решения.

---

Постановка задачи и выбор метода

Для решения задачи был применён метод максимальной причинной энтропии (Maximum Causal Entropy IRL, MCE IRL). Ключевое отличие MCE IRL от прямых методов обучения состоит в следующем: вместо того чтобы непосредственно имитировать наблюдаемые действия эксперта, алгоритм восстанавливает функцию вознаграждения — то есть выясняет, какие состояния среды эксперт неявно считал «хорошими» или «плохими». Из восстановленной функции вознаграждения затем выводится оптимальная политика принятия решений. Принцип максимальной причинной энтропии при этом обеспечивает, что среди всех политик, согласующихся с наблюдаемым поведением эксперта, выбирается наименее предположительная — то есть та, которая не приписывает эксперту лишних намерений, не подтверждённых данными.

---

Дискретизация пространства состояний

Поскольку метод MCE IRL в табличной постановке требует конечного пространства состояний, непрерывные и малокардинальные признаки были преобразованы в дискретные. Для каждого признака применялась следующая логика: если число уникальных значений не превышало установленного предела (четыре), признак сохранял свою естественную структуру — каждое уникальное значение получало собственный номер. Если же признак был непрерывным, его диапазон разбивался на перцентильные интервалы равной наполненности, что обеспечивало равномерное распределение наблюдений по бинам. Бинарные поля can_take2 и can_take1 имели лишь два возможных значения и дискретизировались тривиально. Поле drain_delay_h1 как непрерывная величина разбивалось по перцентилям. Каждый вектор признаков в итоге отображался в единственный целочисленный индекс состояния, однозначно идентифицирующий комбинацию дискретных значений всех трёх признаков. Итоговое пространство состояний представляло собой декартово произведение бинов по каждому из признаков.

---

Построение модели переходов между состояниями

Для применения MCE IRL необходимо было формализовать среду в виде марковского процесса принятия решений — задать вероятности переходов между состояниями при каждом из возможных действий. Матрица переходов строилась непосредственно из экспертного датасета: для каждого последовательного шага траектории фиксировался факт перехода из текущего состояния в следующее при конкретном действии эксперта. Таким образом, вероятности переходов извлекались из реального поведения среды, а не задавались аналитически. Для состояний, в которых наблюдений не было, использовался малый равномерный сдвиг во избежание нулевых вероятностей. Матрица нормализовалась по строкам, превращая счётчики переходов в корректное вероятностное распределение. Дополнительно для каждого состояния вычислялся средний вектор наблюдений по всем временным срезам, в которых это состояние было посещено, — он использовался как числовое представление состояния при вычислении вознаграждения нейронной сетью.

---

Вычисление меры посещаемости состояний экспертом

Ключевым объектом сравнения в MCE IRL является мера посещаемости состояний (occupancy measure) — распределение, отражающее, как часто эксперт оказывался в каждом из состояний на протяжении всей траектории. Эта мера вычислялась путём подсчёта числа попаданий каждого состояния в последовательности дискретизированных индексов и нормировки на общее число шагов. По своей сути данная характеристика кодирует предпочтения эксперта: состояния, в которых он оказывался часто, с большой вероятностью соответствуют высокому вознаграждению. Именно согласование меры посещаемости модели с мерой посещаемости эксперта является целью оптимизации в MCE IRL.

---

Обучение функции вознаграждения

Функция вознаграждения была параметризована нейронной сетью, принимающей на вход числовое представление состояния и возвращающей скалярную оценку. Архитектура сети включала один скрытый слой из 64 нейронов; вознаграждение зависело исключительно от состояния, но не от самого действия и не от следующего состояния, что отражает предположение об автономности оценки ситуации агентом. Обучение выполнялось на протяжении 100 итераций методом градиентного спуска со скоростью обучения 0.01 и коэффициентом дисконтирования будущих вознаграждений 0.99. На каждой итерации алгоритм решал прямую задачу: по текущей функции вознаграждения вычислял оптимальную политику методом обратной индукции (мягкий вариант, обеспечивающий принцип максимальной энтропии), затем оценивал меру посещаемости состояний при данной политике и корректировал параметры сети так, чтобы уменьшить расхождение между полученной мерой и мерой посещаемости эксперта.

---

Извлечение политики принятия решений

По завершении обучения из выученной функции вознаграждения была аналитически извлечена оптимальная политика принятия решений. Для каждого состояния вычислялось ожидаемое суммарное дисконтированное вознаграждение при каждом из двух возможных действий (принять или не принять автомобиль), и из этих значений методом обратной индукции получалось распределение вероятностей над действиями. Итогом явилась таблица, сопоставляющая каждому состоянию вероятность выбора действия «принять» (can_take1 = 1). На обучающей выборке политика сопоставлялась с фактическими решениями эксперта: при пороге вероятности 0.5 вычислялась доля корректных предсказаний (accuracy).

---

Сохранение и применение модели

Вся информация, необходимая для воспроизведения модели и применения её к новым наблюдениям, была сохранена в двух файлах. Первый содержал веса нейронной сети, выученную таблицу политики, матрицу переходов, матрицу наблюдений, начальное распределение состояний и гиперпараметры обучения. Второй файл — в удобочитаемом текстовом формате — хранил метаданные: список признаков, точность на обучающей выборке, размерность пространства состояний и параметры дискретизации. При последующем использовании модели для принятия решений в реальном времени новый вектор наблюдений дискретизировался по сохранённым схемам разбиения, преобразовывался в индекс состояния, после чего из таблицы политики извлекалась вероятность действия «принять» — без повторного запуска нейронной сети. Это обеспечивало низкую вычислительную стоимость инференса при полном воспроизведении поведения обученной модели.
