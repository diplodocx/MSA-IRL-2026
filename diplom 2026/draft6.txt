Программная реализация многоагентной симуляции дорожного движения

---

Технологический стек

Симуляция реализована на языке Python с использованием веб-фреймворка Flask и библиотеки Flask-SocketIO, обеспечивающей двустороннюю коммуникацию между серверной логикой и браузерным интерфейсом по протоколу WebSocket. Клиентская часть представлена встроенным HTML-шаблоном с JavaScript-библиотекой Socket.IO, что позволяет отображать состояние среды в реальном времени без перезагрузки страницы. Логика управления очередями реализована с применением структуры данных deque из стандартной библиотеки Python, а параллельное исполнение симуляционного цикла и обработки сетевых запросов обеспечивается многопоточностью через модуль threading.

---

Реализация структуры среды

Дорожная топология — одна главная полоса, разветвляющаяся на две дополнительные, — реализована в виде трёх независимых очередей с ограниченной ёмкостью: main_line (вместимость 12 автомобилей), highway1 и highway2 (вместимость по 10 автомобилей каждая). Каждая очередь моделирует участок дороги, а единица в массиве соответствует одному автомобилю, занимающему позицию в полосе. Ограниченная вместимость реализует физическое ограничение пропускной способности дорожного сегмента: при достижении максимального числа элементов очередь перестаёт принимать новые автомобили, что воспроизводит эффект образования пробки.

---

Реализация временны́х характеристик среды

Четыре временны́х параметра среды отображены на конфигурационный словарь sim_cfg, значения которого могут изменяться в режиме реального времени через пользовательский интерфейс. Задержка подачи автомобилей в главную полосу (main_delay) задаёт интервал, с которым новые автомобили поступают в main_line извне, — тем самым моделируется интенсивность входящего транспортного потока. Задержка перевода (transfer_delay) определяет темп, с которым автомобили перемещаются из main_line в одну из дополнительных полос, воспроизводя пропускную способность разветвления. Параметры drain_delay_h1 и drain_delay_h2 задают независимую пропускную способность выхода из highway1 и highway2 соответственно: с заданной периодичностью первый элемент соответствующей очереди удаляется, имитируя проезд автомобиля через регулируемый участок. Все четыре параметра волатильны — они могут изменяться пользователем в ходе работы симуляции посредством ползунков на веб-интерфейсе, что обеспечивает динамическое изменение характеристик среды в реальном времени.

---

Реализация агентной маршрутизации

Маршрутизация автомобилей из main_line в дополнительные полосы определяется двумя независимыми управляющими сигналами готовности — по одному на каждую полосу. Каждый агент располагает сведениями исключительно о своей полосе и транслирует своё решение в виде двоичного флага.

Агент, связанный с highway1, представлен параметром can_take1, принимающим значение 0 или 1. Данный параметр управляется пользователем через кнопку-переключатель на интерфейсе: нажатие инвертирует текущее значение, сигнализируя о готовности либо неготовности полосы принять автомобиль. В коде значение хранится в словаре sim_cfg и обновляется через обработчик события set_param.

Агент, связанный с highway2, реализован в виде функции can_take2, которая вычисляет своё решение автономно: если текущая длина очереди highway2 не превышает настраиваемый порог threshold, функция возвращает 1 (агент готов), иначе — 0 (агент закрыт). Порог threshold управляется пользователем через ползунок, что позволяет динамически регулировать чувствительность агента к собственной загруженности.

Итоговое решение о переводе автомобиля формируется в симуляционном цикле на основе совместных сигналов обоих агентов по следующим правилам: если оба агента недоступны, перевод не производится; если оба готовы, целевая полоса выбирается случайно с равной вероятностью посредством вызова random.random(); если готов лишь один из агентов, автомобиль направляется на его полосу.

---

Механизм симуляционного цикла и визуализации

Вся динамика среды сосредоточена в функции sim_loop, исполняемой в отдельном потоке. Цикл с шагом 50 миллисекунд последовательно проверяет, наступил ли момент для каждого из четырёх событий (добавление в main_line, перевод в highway, выезд из highway1, выезд из highway2) и при необходимости производит соответствующую операцию с очередью. После каждого изменения состояния серверная часть рассылает актуальный снимок всех трёх очередей подключённым клиентам через WebSocket. Браузерный интерфейс немедленно отражает полученные данные, визуализируя заполненность каждой полосы в виде горизонтальной шкалы из ячеек, где закрашенная ячейка соответствует автомобилю, а пустая — свободной позиции в очереди. При переходе агента highway2 в состояние готовности 0 соответствующая визуальная полоса подсвечивается красным цветом, сигнализируя о блокировке направления.

---

Механизм случайного изменения среды

Для моделирования непредсказуемых изменений условий среды в симуляцию включена функция randomize, доступная через кнопку на интерфейсе. При её вызове всем временны́м параметрам среды (main_delay, transfer_delay, drain_delay_h1, drain_delay_h2) и порогу агента highway2 (threshold) присваиваются случайные значения в пределах допустимых диапазонов каждого из ползунков. Значения немедленно применяются к симуляции и отображаются на интерфейсе, что позволяет исследовать поведение агентов в динамически меняющихся условиях без ручной настройки параметров.
