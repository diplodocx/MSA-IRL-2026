# Описание диаграммы прецедентов

Диаграмма описывает взаимодействие оператора с графическим интерфейсом симуляционной системы многоагентного взаимодействия.

## Актор

**Оператор** — пользователь, взаимодействующий с системой через веб-браузер. Выполняет роль эксперта: управляет симуляцией, задаёт параметры среды, принимает решения о маршрутизации транспортных единиц и фиксирует свои действия для последующего обучения модели.

## Прецеденты

1. **Управлять симуляцией** — оператор запускает, приостанавливает или сбрасывает симуляционный цикл при помощи кнопок «Старт», «Стоп» и «Сброс». Сброс очищает все транспортные очереди и возвращает систему в исходное состояние.

2. **Настроить параметры транспортной среды** — оператор регулирует динамические характеристики среды через ползунки: интенсивность входящего потока, скорость перевода между полосами, пропускную способность каждого из двух альтернативных маршрутов, а также пороговое значение заполненности для автоматического агента. Изменения применяются мгновенно в реальном времени.

3. **Наблюдать состояние транспортных потоков** — центральная панель отображает три полосы движения в виде цветовых ячеек с числовыми счётчиками заполненности. Визуализация обновляется в реальном времени после каждого шага симуляции. Также отображаются статусные бейджи работы симуляции и записи данных.

4. **Принять решение о маршрутизации** — оператор переключает готовность первой полосы к приёму автомобиля (кнопка-переключатель). Это ключевое экспертное действие, формирующее обучающую выборку. Готовность второй полосы вычисляется автоматически по пороговому правилу и отображается в виде пассивного индикатора. В финальной версии системы данное решение принимается обученной моделью автоматически, а интерфейс отображает результат в режиме «только чтение» с указанием вероятности принятого решения.

5. **Записать экспертные демонстрации** — оператор активирует и завершает запись состояния среды. Система фиксирует наблюдаемые параметры и решения оператора с интервалом в одну секунду и сохраняет результат в файл.

6. **Рандомизировать параметры среды** — оператор нажимает кнопку, генерирующую случайные значения для всех параметров среды в допустимых диапазонах. Прецедент расширяет настройку параметров, обеспечивая разнообразие экспериментальных сценариев и покрытие пространства состояний в демонстрациях.

## Связи между прецедентами

- **«Рандомизировать параметры среды»** расширяет (`<<extend>>`) **«Настроить параметры транспортной среды»**: рандомизация является альтернативным способом задать конфигурацию вместо ручной настройки каждого ползунка.

- **«Принять решение о маршрутизации»** включает (`<<include>>`) **«Наблюдать состояние транспортных потоков»**: решение о готовности полосы принимается на основании визуальной информации о заполненности очередей.

- **«Записать экспертные демонстрации»** включает (`<<include>>`) **«Наблюдать состояние транспортных потоков»**: в процессе записи оператор непрерывно отслеживает состояние системы для принятия обоснованных решений.

# Описание графического интерфейса

## 1. Общая компоновка и цветовая схема

Интерфейс представляет собой одностраничное веб-приложение с тёмной цветовой темой. Компоновка вертикальная, элементы центрированы по горизонтали. Интерфейс разделён на три визуальных уровня сверху вниз:

- **(A)** Сцена дорожной сети — визуализация очередей
- **(B)** Строка счётчиков и статусных бейджей
- **(C)** Панель управления — кнопки, ползунки, индикаторы

Цветовое кодирование единообразно во всех элементах:

| Цвет | Назначение |
|------|------------|
| Бирюзовый | Главная полоса |
| Пурпурный | Первая дополнительная полоса |
| Зелёный | Вторая дополнительная полоса |
| Оранжевый | Кнопка рандомизации |
| Фиолетовый | Индикатор модели и логирования |

## 2. Сцена дорожной сети (верхняя часть)

Горизонтальный контейнер, разделённый на три зоны:

**Левая зона — главная полоса.** Горизонтальная полоса из 12 ячеек. Занятые ячейки окрашиваются в бирюзовый с эффектом свечения, пустые остаются тёмно-серыми.

**Центральная зона — развилка.** Вертикальный разделитель со стрелочными индикаторами, обозначающий точку разветвления потока.

**Правая зона — два маршрута.** Два горизонтальных блока друг над другом: первая полоса (10 пурпурных ячеек) и вторая полоса (10 зелёных ячеек). При отказе второй полосы от приёма её блок подсвечивается красным ореолом.

Визуализация обновляется в реальном времени: сервер транслирует состояние всех очередей после каждой итерации, клиент перерисовывает ячейки с плавной анимацией.

## 3. Строка счётчиков и статусных бейджей (средняя часть)

Горизонтальная строка, содержащая:

- Три числовых счётчика заполненности очередей в формате «N / max» для каждой из полос.
- Бейдж состояния симуляции: «РАБОТАЕТ» (бирюзовый) или «СТОП» (пурпурный).
- Бейдж состояния логирования (в прототипе): «ЗАПИСЬ» (фиолетовый) или «ВЫКЛ» (серый).

## 4. Панель управления (нижняя часть)

Тёмная панель с элементами управления, сгруппированными в блоки.

### Управление симуляцией

Четыре кнопки в горизонтальном ряду:

- **«Старт»** (бирюзовая) — запуск симуляционного цикла;
- **«Стоп»** (пурпурная) — остановка цикла;
- **«Сброс»** (серая) — очистка очередей и остановка;
- **«Random»** (оранжевая) — случайная генерация значений всех параметров среды в допустимых диапазонах.

### Логирование данных (только прототип)

Две кнопки:

- **«Начать лог»** (фиолетовая) — запуск записи состояния среды;
- **«Сохранить лог»** — завершение записи и сохранение файла.

При сохранении в углу экрана появляется уведомление с именем файла.

### Индикаторы и решения маршрутизации

**В прототипе:** кнопка-переключатель готовности первой полосы (зелёная при разрешении, серая при запрете). Оператор нажимает для изменения решения.

**В финальной версии:** пассивный индикатор, отображающий бинарное решение обученной модели (0 или 1), метку «MCE IRL» и вероятность решения в процентах. Элемент доступен только для чтения.

**Индикатор готовности второй полосы:** пассивная цветовая точка (зелёная — готова, пурпурная — не готова), вычисляемая автоматически по пороговому правилу.

**Ползунок порога второй полосы** (1–10): определяет уровень заполненности, при превышении которого полоса отказывает в приёме.

### Ползунки параметров среды

Четыре ползунка, каждый с подписью и отображением текущего значения:

| Параметр | Диапазон | Цвет акцента |
|----------|----------|--------------|
| Интенсивность входящего потока | 0.2–4.0 с | Бирюзовый |
| Скорость маршрутизации | 0.1–4.0 с | Бирюзовый |
| Пропускная способность первой полосы | 0.1–8.0 с | Пурпурный |
| Пропускная способность второй полосы | 0.1–8.0 с | Зелёный |

Изменение любого ползунка мгновенно применяется к работающей симуляции. Значения синхронизируются между сервером и всеми подключёнными клиентами в реальном времени.
